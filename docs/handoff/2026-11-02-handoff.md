## 3. Stack

- Monorepo pnpm 9.12.0 (workspaces), TypeScript 5.9 estricto, ESLint 9 y Prettier.
- `packages/shared`: esquemas Zod 4 compartidos por API y web.
- `prisma/`: Prisma ~6.19, PostgreSQL con CITEXT y restricciones CHECK. Migraciones y seed.
- `apps/api`: NestJS 11 + Fastify (CommonJS, `@Inject` explícito, sin `emitDecoratorMetadata`). Sesiones en Redis, CSRF, Turnstile, email (Mailpit en local), imágenes en S3/MinIO. Tests con Vitest y Testcontainers.
- `apps/web`: React + Vite 6, Tailwind, componentes estilo shadcn (escritos a mano), TanStack Query, MSW para mocks, Vitest.
- `infra/docker-compose.yml`: Postgres, Redis, MinIO (imagen `pgsty/minio`) y Mailpit.

## 4. Arrancar en local

Requisitos: Docker y pnpm (`npm i -g pnpm@9.12.0`).

```bash
pnpm install
pnpm infra:local:up                      # usa infra/docker-compose.local.yml + .env.local
pnpm db:deploy && pnpm db:seed           # solo la primera vez o tras borrar volúmenes
pnpm --filter @party-finder/api dev      # http://localhost:3000
pnpm --filter @party-finder/web dev      # http://localhost:5173
```

- Sin backend: `pnpm --filter @party-finder/web dev:mocks` (MSW).
- Usuarios del seed: `ana`, `bruno`, `carla` (verificados) y `dani` (sin verificar). Contraseña: `party-finder-dev`.
- Mailpit: http://localhost:8025. Consola MinIO: http://localhost:9001.
- El login tiene límite de 5 intentos por minuto: un 429 al repetir logins es lo esperado.

### Ficheros de entorno

- `.env.local` (en `.gitignore`): el que se usa en local. Tiene `DATABASE_URL` y `REDIS_URL` correctos y un `SESSION_SECRET` aleatorio.
- `.env`: plantilla original. Sus `DATABASE_URL` y `REDIS_URL` **no coinciden** con las credenciales de Postgres y Redis del mismo fichero, así que no sirve tal cual para levantar la app.
- `prisma.config.ts` carga `.env.local` y después `.env` (gana `.env.local`).
- La API importa `apps/api/src/config/load-env.ts` lo primero en `main.ts`, para que `@prisma/client` no cargue `.env` antes que `.env.local`.

## 5. Qué hay construido

### API (`apps/api/src`)

Módulos: `auth`, `users`, `mail`, `event-templates`, `uploads`, `calendar`, `attendance`, `health`, más `common` y `config`.

- Todos los endpoints del contrato v2.0.0, incluida la verificación de email.

- Barra lateral, calendario mensual y panel derecho.

- `/identificarse`, `/registro` y `/verificar-email`.
- Estados de carga, error y vacío. Gestión del 429 mostrando el tiempo de espera.
- Comprobación en navegador (Chromium, script Playwright desechable, no está en el repo): 33 comprobaciones OK contra la API real.

## 6. Decisiones y desviaciones del plan

Para revisar por Security:

- Rate limiter propio sobre Redis en lugar de `@nestjs/throttler`.
- Comprobación propia de la firma de bytes de las imágenes en lugar de `file-type`.
- `GET /auth/csrf` crea sesiones anónimas.
- La web no envía Content Security Policy (el plan no la pide).

Otras:

- Diálogo de confirmación antes de borrar (no estaba en el plan), porque borrar una entrada también elimina a sus asistentes.
- Capacidad por defecto 1 cuando la plantilla no indica número de asistentes.
- `Referrer-Policy` solo en `/verificar-email`.
- Sin reglas ESLint de `react-hooks`.
- El bundle de la web avisa de un chunk de 653 kB.
- En móvil el calendario se desplaza en horizontal.

## 7. Limitaciones conocidas

- **Node local 20.9**, y el proyecto pide `>=20.19` (CI usa 22). Obligó a usar versiones más antiguas y algunos apaños de paquetes. Vitest resuelve internamente Vite 7, que oficialmente necesita Node 20.19 o superior, aunque funciona. Se recomienda pasar a Node 22.
- En el Bash de la herramienta el PATH falló a veces. En PowerShell, añadir `C:\Users\aleix\AppData\Roaming\npm` al PATH si no se encuentra `pnpm`.
- `prisma migrate dev` necesita terminal interactiva. En entornos no interactivos usar `pnpm db:deploy`.
